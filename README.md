# Manage Project Sessions

一个用于复杂软件项目的 Codex 个人技能。它帮助 Codex 判断当前工作应该继续、拆分还是切换，并用项目文件、Git、验证结果和运行现场保持任务之间的连续性。

## 它能做什么

- 在实质性工作开始、结束或边界变化时检查当前任务是否仍然合适；
- 为复杂项目建立“项目总控 + 专题任务”的轻量协作结构；
- 让专题在完成或出现跨专题依赖时向项目总控汇报，由总控统一安排下一步；
- 在切换前保留实际状态、变更、验证、未解决事项和易变现场；
- 为新专题选择 Local 或 Worktree，并在正式写代码前检查 Codex 模式。

技能依据当前项目事实做判断，不按消息数量或聊天长度机械切换。

## 核心规则

### 两层会话管理

- `$manage-project-sessions` 是决策层，负责判断继续、拆分、汇报或切换。
- 项目的 `AGENTS.md` 是检查点层，负责在阶段变化、跨专题协作、独立验收、发布准备等节点主动调用技能。
- 如果工作仍在同一目标、所有者和验收边界内，Codex 会安静地继续，不增加额外流程。

### 项目总控与专题任务

复杂、长期项目可以建立一个轻量项目总控，用于维护当前阶段、优先级、跨专题依赖和下一项有依据的专题。

专题任务只负责一个明确结果。专题完成、需要其他专题协作或必须改变阶段和所有者时，应向可验证的项目总控汇报实际状态、变更、验证、未解决事项和一个下一步建议，然后停止扩展范围。

项目总控是专题编排的唯一入口，但不是超级权限。创建、交接、恢复、切换、进入、重命名、归档或删除任务，仍需用户对具体操作明确授权。短项目或单一所有者项目不必强制建立项目总控。

### Local、Worktree 与 Codex 模式

- 新建专题默认使用当前项目的 **Local** 工作目录。
- 只有用户明确要求并行隔离，或存在具体的并行写入冲突时，才使用 **Worktree**。
- 正式写入源码、测试、可执行脚本或影响运行行为的配置前，必须确认当前任务处于 **Codex 模式**。
- 普通说明文档编辑、只读检查、诊断和计划不触发 Codex 模式门禁。

## 安装

先克隆仓库：

```powershell
git clone https://github.com/jamthy/manage-project-sessions.git
```

Windows PowerShell：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE\.codex\skills" | Out-Null
Copy-Item -Recurse -Force .\manage-project-sessions\manage-project-sessions "$env:USERPROFILE\.codex\skills\"
```

macOS 或 Linux：

```bash
mkdir -p ~/.codex/skills
cp -R ./manage-project-sessions/manage-project-sessions ~/.codex/skills/
```

安装后检查 Codex 的技能列表中是否出现 `manage-project-sessions`。如果没有，重新启动 Codex 后再检查。

## 使用指引

### 在全新项目中使用

推荐提示词：

```text
请使用 $manage-project-sessions 管理这个全新项目。
先核对当前项目指令和 Git 状态，并为当前项目启用两层会话管理策略。
根据项目规模判断是否需要项目总控；如果需要，只给出建议的总控任务标题、职责、输入和停止条件，未经我明确授权不要创建任务。
后续每次只推荐一个有依据的下一动作。
```

技能预期动作：

1. 只读检查项目目录、Git 和适用的 `AGENTS.md`；
2. 在本次提示词授权的范围内，将项目检查点策略写入适用的项目指令；
3. 判断项目是否需要总控和专题结构，不为短项目强加复杂流程；
4. 如果需要总控，给出任务标题、职责、输入、允许范围和停止条件；
5. 等待用户明确授权后，才执行具体任务操作；
6. 后续依据仓库、Git、验证和运行现场维护项目连续性。

如果只想先查看建议、不修改项目指令，把提示词中的“并为当前项目启用”改为“评估是否需要启用”。

### 在已有项目中使用

推荐提示词：

```text
请使用 $manage-project-sessions 接管当前已有项目的会话管理。
先只读核对适用的 AGENTS.md、当前阶段、Git、已完成和未完成事项、验证证据及运行现场，不要把聊天历史当作当前事实。
审计现有项目总控和专题任务结构，判断当前工作应继续、向总控汇报，还是建议新的专题边界。
需要修改项目指令或执行任何任务操作时，先取得我的明确授权。
```

技能预期动作：

1. 从项目文件、Git、测试和当前运行状态重建可信现状；
2. 将项目检查点策略分类为已采用、缺失、冲突或无法验证；
3. 核对现有总控、专题边界、跨专题依赖和未关闭事项；
4. 同一目标和所有者内的普通编辑、测试与澄清继续在当前任务完成；
5. 专题完成或需要跨专题协作时，只向项目总控提交最小关闭证据；
6. 由项目总控给出唯一下一专题建议，并在用户授权后执行具体任务操作。

## 重要边界

- 自动审计默认只读；除非用户明确要求启用或更新策略，否则不会修改项目指令。
- 会话管理不授权修改业务事实、提交、推送、发布、部署或执行破坏性操作。
- 聊天记录和任务交接只是历史线索，当前仓库、Git、验证证据和运行状态才是事实依据。
- 项目总控保持轻量，不承担批量实现、长时间诊断或专题内的详细设计。
- 无法确认项目总控的精确任务身份时，专题会停在当前边界，不会根据标题或列表位置猜测。
