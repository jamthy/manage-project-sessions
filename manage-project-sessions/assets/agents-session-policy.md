## 项目会话连续性

在持续进行复杂项目工作时，无需等待用户提到“会话”或“切换”；遇到以下任一事件，调用 `$manage-project-sessions` 进行一次轻量会话边界检查：

- 开始或完成一项实质性任务；
- 切换项目阶段、语义所有者、子系统或主要交付物；
- 进入长时间诊断，或积累了被否决、互相矛盾的路径；
- 开始独立评审、验收、发布准备、项目接管或跨时间继续工作；
- 发现上下文漂移，或即将交接且工作无法从持久项目事实中安全重建。

不得仅根据消息数量或上下文长度决定切换。如果证据表明应继续当前任务且无需用户操作，则安静地继续正常工作，不单独输出会话管理报告。如果需要用户关注，只推荐以下一个动作：继续当前任务、创建专题任务、完成交接后切换、从交接恢复，或暂不切换。说明判断证据以及切换前必须完成的最小收尾。

在实际状态、决策、变更产物、验证证据、未解决事项、相关 Git 或易变现场状态，以及下一步安全动作尚未记录到经过验证的交接中之前，不得交接并切换。

未经用户对该项操作的明确授权，不得创建、进入、重命名、归档或删除 Codex 任务。本策略不授权修改项目事实、提交、推送、发布、外部写入或破坏性操作。
